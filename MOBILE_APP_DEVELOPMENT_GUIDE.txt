SCREEN 1: SPLASH SCREEN (/splash)
--------------------------------------------------------------------------------
1. PURPOSE & USER STORY:
   Initial mobile bootstrapper. Checks if a valid session exists in local storage
   and verifies workspace subscription access before routing into the CRM or Welcome screen.

2. FUNCTIONALITY CHECKS & GUARDS:
   - Check 1 (Session Existence): Call `supabase.auth.getSession()`. If null -> route to /welcome.
   - Check 2 (Profile & Role Hydration): If session exists, query `profiles` for `account_id` and `account_role`.
   - Check 3 (Subscription Guard - checkUserAccess): Call `/api/account/status`.
     * Status must be strictly "active".
     * `expiry_date` must be present and in the future (`new Date(expiryDate) > new Date()`).
     * If `isAllowed == false` -> route to `/onboarding` with reason.
     * If `isAllowed == true` -> route to `/inbox`.

3. DATA FETCHING SPECIFICATION:
   - Local Session Check:
     `const { data: { session } } = await supabase.auth.getSession()`
   - Profile Fetch:
     `const { data: profile } = await supabase.from("profiles").select("id, user_id, full_name, email, avatar_url, account_id, account_role, status, expiry_date").eq("user_id", session.user.id).single()`
   - Account Access Verification API:
     `GET /api/account/status`
     Header: `Authorization: Bearer ${session.access_token}`
     Response Schema: `{ isAllowed: boolean, status: string, expiryDate: string | null, reason: "inactive"|"expired"|"no_expiry"|null, email: string }`

4. FIELD-BY-FIELD & OPTION-BY-OPTION UI BREAKDOWN:
   - Brand Icon: Animated SVG WhatsApp Orbit icon.
   - Activity Indicator: Native loading spinner (Color: Emerald #10B981).
   - App Version Label: "v0.8.0 • WhatsApp Business Cloud CRM" (Text, 11pt, Muted).

5. MOBILE TYPESCRIPT IMPLEMENTATION PATTERN:
```typescript
// SplashScreen.tsx
export function SplashScreen({ navigation }: any) {
  useEffect(() => {
    const verifySession = async () => {
      try {
        const { data: { session } } = await supabase.auth.getSession();
        if (!session?.user) { navigation.replace("Welcome"); return; }
        const res = await fetch(`${API_BASE_URL}/api/account/status`, {
          headers: { Authorization: `Bearer ${session.access_token}` },
        });
        const statusData = await res.json();
        if (statusData.isAllowed) {
          navigation.replace("Inbox");
        } else {
          navigation.replace("Onboarding", { reason: statusData.reason });
        }
      } catch (err) {
        navigation.replace("Welcome");
      }
    };
    verifySession();
  }, []);
  return <View style={styles.container}><ActivityIndicator color="#10b981" size="large" /></View>;
}
```

SCREEN 11: MESSAGE THREAD SCREEN (/inbox/:conversationId)
--------------------------------------------------------------------------------
1. PURPOSE & USER STORY:
   1-on-1 live chat interface with customer. Displays rich message bubbles, delivery statuses,
   reactions, quoted replies, and handles the Meta 24-hour messaging window rule.
   MANDATORY PERFORMANCE RULE: Never fetch all messages at once! Initial fetch retrieves ONLY
   the latest 24 messages. On scrolling to the top, it dynamically fetches the next 24 older messages.

2. FUNCTIONALITY CHECKS & GUARDS:
   - Check 1 (24-Hour Policy Window Calculation):
     ```typescript
     // Find the most recent inbound message from customer:
     const lastCustomerMsg = messages.filter(m => m.sender_type === "customer").pop();
     const isExpired = lastCustomerMsg
       ? (Date.now() - new Date(lastCustomerMsg.created_at).getTime()) > 24 * 60 * 60 * 1000
       : true;
     ```
     * If `isExpired == true`: Lock composer text input. Show amber warning banner:
       "24-Hour WhatsApp messaging window is closed. Only Meta-approved templates can be sent."
       Provide "Send Template" button opening the Template Picker.
   - Check 2 (Role Check): Viewers (`account_role === "viewer"`) cannot send messages.
   - Check 3 (Pagination State Guards):
     * `hasMoreOlder: boolean` (Set to false when query returns fewer than 24 rows).
     * `isLoadingOlder: boolean` (Prevents duplicate parallel requests while scrolling up).

3. DATA FETCHING SPECIFICATION: 24-MESSAGE CHUNKED PAGINATION ENGINE:
   A. INITIAL LOAD - LATEST 24 MESSAGES ONLY:
      ```typescript
      const PAGE_SIZE = 24;

      async function fetchLatest24Messages(conversationId: string) {
        const { data, error } = await supabase
          .from("messages")
          .select("*, reactions:message_reactions(*)")
          .eq("conversation_id", conversationId)
          .order("created_at", { ascending: false }) // NEWEST FIRST
          .limit(PAGE_SIZE);

        if (error) throw error;

        // Determine if more historical messages exist
        setHasMoreOlder(data.length === PAGE_SIZE);

        // Reverse into chronological order (oldest -> newest) for display
        const chronological = [...data].reverse();
        setMessages(chronological);

        // Scroll to bottom immediately upon rendering initial 24
        setTimeout(() => {
          scrollViewRef.current?.scrollToEnd({ animated: false });
        }, 50);
      }
      ```

   B. SCROLL TO TOP - LOAD NEXT 24 OLDER MESSAGES:
      Triggered when the user scrolls to the top of the chat (e.g. `onScroll` offset <= 20 or pull-to-refresh).
      ```typescript
      async function loadOlder24Messages() {
        if (!hasMoreOlder || isLoadingOlder || messages.length === 0) return;

        setIsLoadingOlder(true);
        const oldestLoadedMessage = messages[0]; // Top-most message currently displayed

        try {
          const { data, error } = await supabase
            .from("messages")
            .select("*, reactions:message_reactions(*)")
            .eq("conversation_id", conversationId)
            .lt("created_at", oldestLoadedMessage.created_at) // CURSOR: Strictly older
            .order("created_at", { ascending: false }) // NEWEST OF OLDER CHUNK
            .limit(PAGE_SIZE);

          if (error) throw error;

          if (data) {
            if (data.length < PAGE_SIZE) {
              setHasMoreOlder(false); // Reached beginning of chat history
            }

            // Reverse older slice into chronological order
            const olderChronological = [...data].reverse();

            // Prepend older 24 messages to current list:
            setMessages(prevMessages => [...olderChronological, ...prevMessages]);
          }
        } catch (err) {
          console.warn("Error loading older messages:", err);
        } finally {
          setIsLoadingOlder(false);
        }
      }
      ```

   C. SCROLL VIEW HOOKUP & TOP DETECTION:
      ```tsx
      <ScrollView
        ref={scrollViewRef}
        onScroll={({ nativeEvent }) => {
          // Detect when user scrolled to top (contentOffset.y <= 15)
          if (nativeEvent.contentOffset.y <= 15 && hasMoreOlder && !isLoadingOlder) {
            loadOlder24Messages();
          }
        }}
        scrollEventThrottle={32}
        refreshControl={
          hasMoreOlder ? (
            <RefreshControl
              refreshing={isLoadingOlder}
              onRefresh={loadOlder24Messages}
              tintColor="#10B981"
              title="Loading older messages..."
            />
          ) : undefined
        }>
        {isLoadingOlder && (
          <View style={{ paddingVertical: 10, alignItems: "center" }}>
            <ActivityIndicator size="small" color="#10B981" />
            <Text style={{ fontSize: 11, color: "#6B7280", marginTop: 4 }}>Loading earlier messages...</Text>
          </View>
        )}
        {messages.map(item => <MessageBubble key={item.id} message={item} />)}
      </ScrollView>
      ```

   D. REALTIME LIVE INCOMING MESSAGE (APPENDS TO BOTTOM):
      When a new WhatsApp message arrives in real-time, it is appended to the bottom:
      ```typescript
      supabase
        .channel(`messages:${conversationId}`)
        .on("postgres_changes", { event: "INSERT", schema: "public", table: "messages" }, (payload) => {
          const newMsg = payload.new;
          setMessages(prev => {
            // Deduplicate if already optimistic
            if (prev.some(m => m.id === newMsg.id)) return prev;
            return [...prev, newMsg];
          });
          // Scroll smoothly to bottom
          setTimeout(() => {
            scrollViewRef.current?.scrollToEnd({ animated: true });
          }, 60);
        })
        .subscribe();
      ```

   - Mark Conversation as Read:
     ```typescript

     ```

3.1 COMPLETE 19-TABLE DATABASE SCHEMA (POSTGRESQL)
--------------------------------------------------
All tables enforce Row-Level Security (RLS) policies scoped to `account_id`.

1. `accounts`
   - id: uuid primary key default gen_random_uuid()
   - name: text not null

   - user_id: uuid not null references auth.users(id) on delete cascade
   - account_id: uuid not null references accounts(id) on delete cascade
   - full_name: text
   - email: text
   - avatar_url: text
   - account_role: text check (account_role in ("owner","admin","agent","viewer")) default "agent"
   - status: text default "active"
   - expiry_date: timestamptz
   - created_at: timestamptz default now()

3. `account_invitations`
   - id: uuid primary key default gen_random_uuid()
   - account_id: uuid not null references accounts(id) on delete cascade
   - role: text check (role in ("admin","agent","viewer")) not null
   - label: text
   - token_hash: text not null
   - expires_at: timestamptz not null
   - accepted_at: timestamptz
   - created_by_user_id: uuid references auth.users(id)

4. `contacts`
   - id: uuid primary key default gen_random_uuid()
   - account_id: uuid not null references accounts(id) on delete cascade
   - user_id: uuid references auth.users(id)
   - phone: text not null
   - phone_normalized: text not null
   - wa_user_id: text
   - wa_username: text
   - name: text
   - email: text
   - company: text
   - avatar_url: text
   - created_at: timestamptz default now()
   - updated_at: timestamptz default now()
   - unique constraint: (account_id, phone_normalized)

5. `tags`
   - id: uuid primary key default gen_random_uuid()
   - account_id: uuid not null references accounts(id) on delete cascade
   - name: text not null
   - color: text not null
   - created_at: timestamptz default now()

   - id: uuid primary key default gen_random_uuid()

   - contact_id: uuid references contacts(id) on delete set null
   - title: text not null
   - value: numeric default 0
   - currency: text default "USD"
   - expected_close_date: date
   - status: text check (status in ("open","won","lost")) default "open"
   - assigned_to: uuid references profiles(id)
   - notes: text

17. `broadcasts` & `broadcast_recipients`
   - broadcasts: id, account_id, name, template_name, template_language, variables, audience, scheduled_at, status, total_recipients, sent_count, delivered_count, read_count, replied_count, failed_count.

18. `commerce_orders` & `commerce_products`
   - commerce_orders: id, account_id, conversation_id, contact_id, order_reference, status ("pending","processing","paid","completed","cancelled"), currency, subtotal, shipping, tax, total_amount, items (jsonb), payment_link_url, paid_at.
   - commerce_products: id, account_id, catalog_id, retailer_id, name, description, price, currency, image_url, availability ("in stock","out of stock").

19. `automations`, `automation_steps`, `automation_logs`
   - automations: id, account_id, name, description, trigger_type, trigger_config, is_active, execution_count.
   - automation_steps: id, automation_id, step_type, step_config, position, parent_step_id, branch ("yes","no").

---------------------------------------------
Mobile client subscribes on mount:
```typescript
// Channel: Messages
const msgChannel = supabase
  .channel(`messages:${accountId}`)
  .on("postgres_changes", { event: "INSERT", schema: "public", table: "messages" }, (p) => onNewMessage(p.new))
  .on("postgres_changes", { event: "UPDATE", schema: "public", table: "messages" }, (p) => onUpdateMessage(p.new))
  .subscribe();

// Channel: Conversations
const convChannel = supabase
  .channel(`conversations:${accountId}`)
  .on("postgres_changes", { event: "*", schema: "public", table: "conversations" }, (p) => onConvChange(p.new))
  .subscribe();

// Channel: Presence
const presenceChannel = supabase.channel(`presence:${accountId}`);
presenceChannel.subscribe(async (status) => {
  if (status === "SUBSCRIBED") {
    await presenceChannel.track({ user_id: currentUserId, online: true });
  }
});
```
